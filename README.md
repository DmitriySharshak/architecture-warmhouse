### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Вкл/Выкл. Операция инициируется пользователем через веб-интерфейс;
- Cервер синхронно отправляет команды на конкретное устройство в доме.

**Мониторинг температуры:**

- Пользователь отслеживает текущую температуру веб-интерфейс или дисплей датчика температуры в доме;
- Сервер с заданной периодичечностью опрашивает датчик температуры в доме и отображает значение.

### 2. Анализ архитектуры монолитного приложения

- Логика приложения написана на языке Go (HTTP, бизнес-логика, взаимодествиие с БД);
- СУБД PostgreSQL как единое хранилища данных для хранения пользователей, домов, устройств, информации о температуре;
- Взаимодействие с датчиками организованно синхронным способом.

### **4. Проблемы монолитного решения**

- Плохая масштабируемость: масштабирование доступно через развертывание нового инстанса, нельзя масштабировать отдельный 
  функциональный блок;
- Синхронное взаимодействие с устройствами: Опрос большого количества датчиков температуры по очереди приводит к долгому отклику и    
  большим задержкам на обработку всех датчиков, как результат возможно исчерпание рабочих потоков 
- Сложность с внесением изменений и развертыванием: выпуск новой версии сопровождается остановкой всей системы, нужны согласованные      тех.окна
- Единая точка отказа всей системы;

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors

Должно при каждом вызове отображаться разное значение температуры
